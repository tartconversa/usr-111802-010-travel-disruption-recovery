# 交通衔接运营业务数据

来源事件有来源编号、事件编号、修订、外部实体、发生时间和观察时间；同一来源同一事件的更高修订替代先前修订。主体映射只在来源与外部标识的组合内有效，无法映射的事件在现有摘要中列为未归属。通用金额是原始事件上的可选数值，不代表利润、节约额或结算结果。

报告发布接口保留报告正文和摘要哈希，相同编号不接受不同内容。业务口径、结论的适用范围和后续变化的影响需要与原始观察区分。

# 联程衔接风险分析

行程目录中每条 leg 的车站为该段乘车站；第 k 段的到达站即第 k+1 段的乘车站，换乘发生在下一段的乘车站。ticket 事件 payload 需含 journey；旅客身份先经主体映射解析，未映射按 来源/外部标识 兜底，同一旅客多张联程票只计一名滞留旅客。schedule 事件 payload 需含 train、station，可含 arrival、departure、seats（可用替代席位）；同一车次同一车站的最新修订为当前时刻，最早观察到的修订为基线。rebook 事件 payload 需含 journey；存在有效改签的（旅客, 行程）视为已处置，不计入仍需处置。

衔接判定：换乘余量 = 后段发车 − 前段到达 − 站内最短换乘时间；余量小于零为衔接中断。中断触发归因：前段到达较基线延后记 arrival_delayed，后段发车较基线提前记 departure_advanced，两者均未不利移动记 planned_insufficient；触发记录携带对应时刻修订的来源、事件号与修订号。缺少时刻或换乘时间的衔接列为 unverifiable，不混入风险结论。

替代席位覆盖：同一换乘站、发车不早于 “前段到达 + 最短换乘” 的其他车次（不含前段到达车次与错过车次）的 seats 合计，与仍需处置旅客数对比，得出 covered 与 shortfall；seats 缺失按零计。同一物理换乘（同站同前后车次）上的旅客合并核对。

处置清单：publish_handling_list 将评估结果连同依据（行程、换乘时间、时刻修订号、车票与改签事件）一并固化，同编号不接受不同内容；新到运行消息不会改动已下发清单。handling_delta 对比当前评估与最近一次下发的清单：new 为新进清单、changed 为风险依据变化、cleared 为解除（reason 取 rebooked / feasible / unverifiable / ticket_withdrawn）、unchanged 无需重复通知。
